# まなぶ塾 — デプロイガイド

## 0. フォルダ構成

```
deploy2/
├─ index.html          … シリーズのトップページ（ハブ）
├─ icon-*.png / apple-touch-icon.png  … ハブ自体のアイコン
├─ nihonshi/            … 「一問一答 日本史」本体
│   ├─ index.html
│   ├─ manifest.json
│   └─ icon-*.png / apple-touch-icon*.png
└─ README.md
```

トップページ(`index.html`)が各分野へのリンク集（今は日本史のみ、準備中の
プレースホルダーも1枚表示）になっていて、実際のクイズアプリは
`nihonshi/` のようにサブフォルダに分野ごとに格納する構成です。
**今後、世界史・地理などを追加するときは、サブフォルダを増やして
トップページにカードを1つ足すだけ**で済むようにしてあります(手順は
下の「7. 新しい分野を追加する」参照)。

デプロイするときは **このフォルダ全体(`deploy2`配下すべて)** をそのまま
アップロードしてください。ビルド不要、外部サーバー不要（データはすべて
ブラウザの localStorage に保存）です。

## 0.5 ホーム画面への追加・アイコンについて

各分野アプリ内の「？」→「このアプリについて」から、iPhone/Androidそれぞれの
ホーム画面への追加手順を案内済みです。**iPhoneもAndroidもどちらも対応可能**
(ネイティブのApp Store/Google Playアプリではなく、ブラウザの「ホーム画面に
追加」機能を使う形。審査不要ですぐ使える一方、Apple/Google公式ストアには
並びません)。

アイコンは同梱の猫マスコットから作成済みで、`manifest.json` と
`<link rel="apple-touch-icon">` 等で既に設定されています。差し替えたい
場合は `icon-192.png` / `icon-512.png` / `icon-maskable-512.png` /
`apple-touch-icon.png` を同じファイル名で上書きしてください。

## 1. まずは独自ドメインで公開する（推奨ルート）

### Vercel を使う場合（一番簡単）
1. https://vercel.com にログイン（GitHubアカウントでOK）
2. ダッシュボードの「Add New → Project」→「Deploy without Git」を選ぶと、
   フォルダをドラッグ&ドロップするだけでデプロイできる
3. この `deploy2` フォルダ（`index.html` が直下にあるフォルダ）を
   そのままドロップ
4. 数十秒で `xxxxx.vercel.app` のURLが発行される(日本史アプリは
   `xxxxx.vercel.app/nihonshi/` に自動で配置される)
5. 独自ドメインを持っている場合は Project Settings → Domains で追加し、
   ドメイン側のDNS（Vercelが指示するCNAME/Aレコード）を設定する

### Cloudflare Pages を使う場合
1. https://dash.cloudflare.com → Workers & Pages → Create → Pages
2. 「Upload assets」を選び、この `deploy2` フォルダをアップロード
3. 発行されたURLを確認 → Custom domains で独自ドメインを追加

どちらも無料枠で十分動きます（静的ファイルだけなので）。

## 2. 独自ドメインを取得する（まだの場合）

お名前.com、ムームードメイン、Cloudflare Registrar などで
`.com` / `.jp` ドメインを取得 → 上記のVercel/Cloudflareにネームサーバーまたは
CNAMEを設定するだけでOK。

## 3. OGP画像・メタ情報を差し替える

`index.html`(トップページ)と `nihonshi/index.html`(日本史アプリ)の
両方の `<head>` 内に、それぞれ以下のようなプレースホルダーがあります。
本番ドメインが決まったら実際のURLに差し替えてください。

```html
<meta property="og:url" content="https://example.com/">
<meta property="og:image" content="https://example.com/ogp.png">
```

- `og:url` → 実際に公開するURL（トップページ用・日本史アプリ用でそれぞれ変える）
- `og:image` → noteやX(Twitter)でシェアされた時に表示される画像
  (1200x630px推奨。まだ無ければ一旦このままでもアプリは問題なく動きます)

## 4. 広告（Google AdSense）を追加する

1. https://www.google.com/adsense/ でアカウント作成し、サイトを登録して審査を申請
   - **審査には「オリジナルで一定量のコンテンツがあるサイト」であることが必要。
     このアプリだけだと審査に通りにくい場合があるので、noteの記事や
     アプリの使い方・歴史検定の勉強法の記事を数本併設しておくと通りやすくなる**
   - 審査には数日〜数週間かかることがある
2. 審査通過後にもらえる publisher ID（`ca-pub-XXXXXXXXXXXXXXXX`）を、
   `nihonshi/index.html` の `<head>` 内、コメントアウトされている以下の行に
   設定してコメントを外す：

   ```html
   <script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXXXXXXXXXXXXXX" crossorigin="anonymous"></script>
   ```

3. 広告を表示したい場所に、同じくコメントアウトしてある `<ins class="adsbygoogle">`
   ブロックがあります（ホーム画面下部、セッション終了後の2箇所に用意済み）。
   AdSense管理画面で広告ユニットを作成し、発行された
   `data-ad-client` / `data-ad-slot` の値に差し替えてコメントを外してください。
4. **プライバシーポリシーページが必要**。AdSenseの利用規約上、Cookie利用や
   広告配信についての説明ページが必須です。簡単な雛形が必要なら声をかけてください。

広告の配置は「ホーム画面の分野一覧の下」と「セッション終了直後の結果画面」の
2箇所を想定済み（ユーザーが読み終えて次の行動に移る直前＝広告のクリック率が
出やすいタイミング）。増やしすぎるとUXが悪化し逆に離脱率が上がるので、
最初はこの2箇所だけで様子を見るのがおすすめ。

## 5. SEOについて

結論から言うと、**隠しテキストで検索ワードを詰め込む、というやり方は
今は通用しないし、むしろGoogleのガイドライン違反でペナルティ(検索結果に
出なくなる)の対象**。昔そういう手法が通用した時期もあったけど、今は
「ユーザーに見えているページの中身」と「検索エンジンへの申告内容」が
一致しているかを重視するアルゴリズムになっている。

実際に効くのは地味だけど以下の積み重ね：

- **`<title>`と`meta description`に、検索されそうな言葉を自然に入れる**
  （すでに設定済み：「歴史能力検定2級」「一問一答」「無料」など）
- **ページ本文にも同じ言葉が実際に書かれていること**
  （「？」の使い方ページに「歴史能力検定2級」「全国通訳案内士試験」
  「共通テスト」と書いたのは、SEO的にも理にかなっている。隠すのではなく
  見える場所に書くのが正解）
- **被リンク**：noteの記事やSNSからこのサイトへのリンクが増えるほど、
  「信頼されているサイト」としてGoogleの評価が上がる
- **表示速度・モバイル対応**：このアプリは軽量な静的ページなので、
  この点はもともと有利
- **ページ数を増やす**：日本史1本だけよりも、世界史・地理…とシリーズの
  分野ページが増えるほど、「〇〇 一問一答」のようなさまざまな検索語で
  引っかかるチャンスが増える。シリーズ化そのものがSEO施策にもなる
- **HTTPS対応**：Vercel/Cloudflareはどちらもデフォルトで対応済み

優先順位をつけるなら、裏側の設定をいじるより「noteで記事を書いて、
検索されそうな言葉を自然に使いながら実際に役立つ内容を書く」ことの方が
効果が大きい。検索エンジンは結局、人間が読んで役に立つかどうかを
色んな角度から推測しようとしているだけ、というイメージを持っておくと
判断しやすい。

## 6. noteで集客する

記事構成の叩き台：

1. **フック**: 「歴史能力検定2級、独学でどう対策する？」
   「参考書だけだと忘れる」など、悩みへの共感から入る
2. **課題提起**: 市販の一問一答アプリは範囲が偏っていたり、有料だったり、
   復習のタイミングを自分で管理しないといけない、という不満点を挙げる
3. **解決策として自作アプリを紹介**:
   - 全19分野・1250問、検定範囲を網羅
   - SM-2という間隔反復アルゴリズムで「忘れかけた頃」に自動で復習問題が出る
   - 無料・登録不要・ブラウザだけで完結
   - スクリーンショットを2〜3枚（ホーム画面、クイズ画面、結果画面）
4. **CTA**: 「こちらから無料で使えます→ [URL]」
5. 検定直前期を狙うなら「試験◯週間前から毎日これだけやればOK」的な
   シリーズ記事にすると回遊性が上がる

最初の記事は無料公開、認知が広がってきたら「詳しい使い方」「分野別の
出題傾向まとめ」などを別記事で展開すると、noteからの継続流入が作りやすい。

## 7. 新しい分野を追加する（シリーズ展開の手順）

例として「世界史」を追加する場合：

1. `nihonshi/` フォルダを丸ごとコピーして `sekaishi/` にリネーム
2. `sekaishi/index.html` を開き、`<script>` 内の `CONFIG` を変更：
   ```js
   var CONFIG = {
     subjectId: "sekaishi",     // 必ず他の分野と重複しない値に
     subjectTitle: "世界史",
     examLabel: "〇〇検定〇級"   // 対応する検定・試験名
   };
   ```
   (`subjectId` を変えることで学習データの保存場所が自動的に分野ごとに
   独立するので、同じドメインに複数分野を置いても進捗が混ざらない)
3. `QUESTIONS` のデータを新しい分野の問題セットに差し替える
   (`ERA_MAP` / `ERA_COLOR` も分野に合わせて書き換える)
4. `<title>` / `meta description` / OGPタグ / `manifest.json` の
   `name` `short_name` `description` を新しい分野向けに書き換える
5. アイコンを新しく作る：これまでと同じ猫キャラクターに、看板の文字だけ
   「世界史」に差し替えたポーズを生成すれば、シリーズとしての一貫性が
   保てる(Geminiなどで生成する際のブリーフが必要なら声をかけてください)
6. トップページ(`index.html`)の「準備中」カードを、実際の
   `<a class="card" href="./sekaishi/">` に差し替える
7. 全体をデプロイし直す(Vercel/Cloudflareともにフォルダを再アップロード
   するだけ)
